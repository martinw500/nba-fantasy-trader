# nba-fantasy-trader (Fantasy GM)

Local Yahoo NBA fantasy GM app. Python 3.13 + pandas backend, one-file vanilla HTML/JS UI. User-facing docs and every workflow: README.md. **What's untested and what to build next: ROADMAP.md.** Read it before starting new work and tick items off as they're done.

## Files
- `model.py`: the engine (`League` class) plus a JSON CLI. All numbers come from here: UI, AI chat and the `/gm` skill.
- `yahoo.py`: league snapshot → `data/league.json`. Yahoo API (read-only, yfpy; access now needs Yahoo's approval), `python yahoo.py import <snapshot>.txt ["Team"]` (Instinct-style league snapshot or a hand-typed list, `parse_text`; unknown sections are skipped; Refresh imports the newest `*snapshot*.txt`; the top-bar dropdown switches your team via `/api/me`), or `python yahoo.py demo` (fake league from real stats).
- `model.py` also fetches the NBA schedule (`nba_api`, cached a day), ESPN's injury feed (cached 3h, archived per day), ESPN's projections (`espn()`, cached a day, archived per day) and this season's box scores (`gamelogs()`, cached 12h, for the player card's recent lines) in `load()`, and passes `news()` (ESPN fantasy news: the player list with ids and latest-news times cached 3h in `news_index()`, a player's items refetched only when that time moves) for the card and My team's News panel (`roster_news()`). News never changes a number. `League` built directly (tests) gets none of them, so it stays offline.
- `app.py`: stdlib `ThreadingHTTPServer` on 127.0.0.1:8765, routes in `api()`.
- `ai.py`: Claude GM via `client.beta.messages.tool_runner`, tools wrap `League` methods, model `claude-opus-5-5`. Only used when `ANTHROPIC_API_KEY` is set; otherwise `/api/chat` runs `claude -p --safe-mode` (`app.py` `claude_chat`) with the gm SKILL.md as system prompt and only `model.py` allowed, plus `WebSearch` when the tab's Web search is on (Model / Effort / Web search are picked on the AI GM tab, validated by `MODELS` / `EFFORTS`). Edit SKILL.md and both `/gm` and the in-app chat follow.
- `backtest.py`: replays a real NBA season (game logs cached in `data/gamelogs_*.csv`) in 20 simulated leagues and prints predicted vs actual win rates. It's the evidence behind the matchup knobs.
- `web/index.html`: the whole UI. State in `S`, views are `view*()` functions returning HTML strings, event delegation via `data-act` / `data-view` / `data-punt`.

## Commands
Python lives in `.venv` (Homebrew Python blocks global pip): use `.venv/bin/python` or `source .venv/bin/activate`.
- `python test_model.py`: self-check, synthetic data, no network. Run it after touching `model.py`.
- `python backtest.py`: calibration check (~1 min). Run it after changing projections or odds maths. `python backtest.py replay`: rest-of-season error by expert weight (fits `PROJ_W`). `python backtest.py teammates`: next week's error with teammates' injuries (fits `SHARE` / `USAGE`, ~3 min). `python backtest.py availability`: each Monday's games-played guess vs the real share, 2024-25 and 2025-26 (fits `AVAIL_*`).
- `python app.py --no-browser`: run the app without opening a tab. `#view` and `?punt=FT%25,TOV` deep-link a view and build.
- `python model.py {team|trade|ideas|search|waivers|movers|roster|week|strategy|news} [--punt ...]`: prints JSON. `strategy` (the punt planner) takes ~15s.

## Model rules (don't break these)
- 9-cat advice (trade, ideas, waivers, standings) runs on the matchup model: `week` (per-game line × GAMES_WEEK × avail, missed games half-filled at waiver level) → `cat_probs` → `_score` → `outlook()`. `_score` is the share of categories won (`settings.scoring` "categories", the default and Martin's league) or `match_prob` ("one_win"). Deltas are in win-% points, `unit: "win%"`. Win-% cutoffs (`TIERS`, `VERDICT`, `MOVE`, `GUARD`, `accept()`) are in One Win terms, scaled by `League.s` (`CAT_SCALE` 0.4 in categories). z-scores (`value()`) are only for player tables and candidate selection.
- DISPERSION, SCHED_CV and PCT_NOISE are fitted by `python backtest.py` (2025-26 box scores, 20 simulated leagues, predictions from what was known each Monday, regulars who sat their team's last game out until a noisy return, `RETURN_NOISE`). Re-run it after changing projections (`baseline()`, `prior()`, `ros()`, availability) and keep the calibration tables near the diagonal. GAMES_WEEK, FILL and STATUS_AVAIL are still guesses. After any change, check standings stay realistic: about 37–59% on the real league as categories since N9's availability (41–57% after N5's IL slots; 37–63% before them; 19–80% as One Win back then). The snake-drafted demo is tighter (~47–52%).
- Category odds are calibrated, so cutoffs live in odds terms: `WEAK` (35%) = weak spot / punt hint, and This week's Ahead/Behind calls use the same cutoff.
- Punts concede the category (`_concede` sets your odds to 0) for your side only. Opponents always use real odds.
- `trade()` rejects players you don't own or that come from more than one team (KeyError). Keep that check, since AI tool input comes through it.
- Values are per game, rest of season: `ros()` = minutes (`GP/(GP+MIN_SHRINK)`, fast: roles change) × production per minute (this season's minutes played vs `SHRINK` games of baseline minutes, slow). Both were picked by replaying 2025-26 rest-of-season lines (Oct 27). `ros()` runs on `prior()`: `baseline()` blended with an expert line at `PROJ_W` (0.6, fitted by `python backtest.py replay` on ESPN's 2025-26 preseason projections). The expert line (`experts()`) is Yahoo's from the snapshot where it has the player, else ESPN's. Yahoo has no minutes: they're ESPN's or ours scaled by output. A rookie's baseline is the fringe line. Availability (`availability()`, N9) counts games in the better of the box-score `baseline()`'s two seasons (its `GP`) at `AVAIL_PAST` of a game and this season's in full, pulled toward `AVAIL_T` by `AVAIL_K` games (rookies: this season toward 85%). Past games barely predict future ones, so availability runs about 61–86% early in the season, not 39–95%.
- Teammates' injuries (`lifts()`): while a regular (`REGULAR`+ min) with an ESPN return date sits, `SHARE` of his minutes go to teammates in the rotation by room under `ROOM` and role similarity, plus `USAGE` of the shots, points, assists and turnovers those minutes don't replace. `ros()` reads this season net of `had()` (the lifts players had while teammates sat), so a boost isn't counted twice. `_boost()` adds the lift for each player's games before the return: rest of season in `p`, this week in `p_week` (`week_vec()` reads it). Lifts only make sense with the injured player sitting; otherwise his minutes count twice. Score `backtest.py teammates` on full weeks: players who miss games that week run 3.6 min under their line, which availability covers.
- "cur"/"Now" = perceived per-game value (`HYPE` shrink). `their_view` uses `perceived()`: that over the games a player plays (`effective()`), floored at waiver level, and an incoming extra player costs the team its weakest players. It's only a note on trades.
- Recent form (Q2): `value(frame="form")` = the last `FORM_DAYS` (14) of `League.logs`, players with `FORM_GP`+ games, z-scored against the rest-of-season pool (`zscores(ref=)`). `trend` arrows and Hot & cold (`movers()`) share one cutoff, `TREND`.
- Trade acceptance runs on the market (N0), never the model's own values: `League.market` = Yahoo Pre/Cur rank blended by `GP/(GP+CHASE)` (20, market only) as a geometric mean (so cold and hot starts move a player alike), re-ranked (model's perceived rank when Yahoo has none, `yahoo` False), valued `100 × MARKET^(rank−1)`. A deal's market (`priced()`) nets out each side's drops (at their market value) and open spots (each `League.spot`, the waiver level's market value fixed at load, never the pickup's own rank: on a free-move copy the best "free agent" can be your own just-dropped Kessler), the same ones the matchup model makes, so `search()` and `trade()` agree. `TIERS` are (your win %, theirs, market gap range); fair also passes with both gaining within `FAIR_FIT`. `accept()` reads the market gap.
- IL slots (N5): `League.il` = {team: players parked in IL / IL+ / NA slots}, `il_n` slots per team (`settings.il`). A parked player holds no active spot, so he counts `week_il`, not `week`: no cover for his missed games, and from his return (`back`, share of games left) he bumps a waiver-level player's week (0 if he wouldn't beat one on `effective()`). Trades keep each side's number of *active* players: injured players coming in park in free IL slots (longest out first), sending a parked player frees no active spot, and an injured player coming in is never the drop. `_after()` and `search()` do the same maths; keep them agreeing (test_model checks it). The daily lineup cap is only in This week (`starts()`): season-long it costs 0.1–0.9% of a team's games (measured Oct 27), so `week` leaves it out.
- `effective()` is the only right way to weight value by availability: values are mostly negative (relative to the rostered average), so `value * avail` would rank an injured player above a healthy one.
- Uneven trades always subtract `n * replacement()`. Replacement = top-5 FA average.
- 9-cat `trade()` and `search()` score on top of `after_free()`: your `free_moves()` (greedy add/drop or open-spot add while one clears `MOVE`) are made first, so a deal gets no credit for a free pickup. The partner is judged on the trade alone (Martin: managers look at the deal, not their waiver options) unless `their_free=True` (Trades toolbar: "Count their waiver moves"). Your pickups are never offered, and the players a deal sends are never dropped (`keep`). `free=False` scores on today's rosters.
- `build()` = a team's weak spots (categories it wins <35% of weeks, `WEAK`). Points-mode trades value opponents on it.
- Player lookup always goes through `League.find()` (accents, Jr/III, typos).
- `SEASON`s are `OLDER`/`LAST`/`CUR` at the top of `model.py`; bump them each October. The baseline blends `LAST` and `OLDER` (`baseline()`). Delete `data/stats_*.csv` to refetch.

## Gotchas
- `nba_api` names have accents (Jokić). Windows consoles need `sys.stdout.reconfigure(encoding="utf-8")`, which the CLIs already do.
- `yahoo.py` hasn't been run against a real league yet. yfpy field access is defensive, but verify the first real pull.
- Browser checks go through the Playwright MCP, which runs headless Microsoft Edge (`PLAYWRIGHT_MCP_BROWSER=msedge` in `~/.claude/settings.json`; Chrome isn't installed). If it fails to start, tell Martin instead of working around it.
- Headless Chromium browsers clamp windows to 504px wide. For phone screenshots, load the app in a 390px iframe.
- Project skills added mid-session don't register until Claude Code restarts.
