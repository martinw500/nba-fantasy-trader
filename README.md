# Fantasy GM

A local app for your Yahoo NBA fantasy league. It tells you who to pick up and drop, tests trades from both sides, finds trades worth proposing, flags sell-high / buy-low players, and helps you pick categories to punt in 9-cat. Points leagues work too. An AI GM chat sits on top and uses the same numbers.

It only reads from Yahoo. You still make the actual moves on Yahoo.

## Setup (5 minutes)

```
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/python app.py
```

That opens http://localhost:8765 with a **demo league**: 12 fake teams drafted from real NBA stats. Everything works on it, so you can try the app before connecting Yahoo.

Homebrew Python blocks a global `pip install`, hence the `.venv`. Where this README says `python`, use `.venv/bin/python` (or run `source .venv/bin/activate` once per terminal; on Windows it's `.venv\Scripts\python`).

### Load your league without the Yahoo API

Since summer 2026, Yahoo only gives Fantasy API access to applications it approves, and approval has no timeline. Until then, load the league from a text snapshot:

1. Get a snapshot of the league as a text file. Instinct's "MCHC FANTASY BASKETBALL - FULL LEAGUE SNAPSHOT" works as-is: league settings, numbered team headings, one fixed-width row per player (`PG    Cade Cunningham    DET - PG,SG  [O: Out]   Pre 5  Cur 41  Ros 100%`), free-agent and waiver sections with roster % and claim dates, this week's matchup totals, transactions, Yahoo projections, adds used, waiver priority and the season schedule. Sections it doesn't recognise are skipped. A hand-typed list works too:
   ```
   ## Toronto blue jays
   Cade Cunningham
   Ivica Zubac (O)
   ```
2. Run `.venv/bin/python yahoo.py import mchc-fantasy-snapshot-2026-10-26.txt`. Your team comes from the file's `My team:` line; name it after the file to pick another (`... import file.txt "fatty zhou"`). It lists any player it couldn't match to NBA stats (usually rookies who haven't played yet).
3. Restart `python app.py`. For a new snapshot, drop the file in the repo folder and press **Refresh**: it imports the newest `*snapshot*.txt` and downloads this season's stats and box scores again (once they're 15 minutes old), so tonight's games count. The sidebar shows when the snapshot was pulled, and every view warns once it's over a day old or its matchup week is over.

   Under that, the sidebar lists how old each downloaded source is: **Stats** and **Box scores** (refreshed every 12 hours, and again once a game goes final), **Schedule** and **Projections** (daily), **Injuries** and **News** (every 3 hours), **Live scores** (nba.com's scoreboard and box scores of games under way: every 30 minutes, every 5 while a game is on). While the app runs it fetches ESPN's injury report again every 30 minutes by itself and recalculates everything; on game nights it also checks a minute after each tip-off and every 5 minutes until the last game is final. The page picks that up when you come back to the tab after 10+ minutes, and This week follows the games every 5 minutes while it's open. Rosters, the snapshot's score and Yahoo's ranks still only change with a new snapshot; tonight's games go on top of that score as they're played (see This week). Hover one for the exact time. An entry turns amber once it's past its refresh time (press **Refresh**), shows **old copy** when the last download failed and the app is using what it had, or **none** when it has never downloaded. A failed or missing source (other than News, which never changes a number, and Live scores, which only matter on game nights and say how old they are in This week) also puts a notice at the top of every view, saying what the numbers leave out. **Refresh** always fetches injuries and live scores again; if that fails, the old copy stays. `python model.py sources` prints the same list.

Pick your team from the dropdown under the league name in the top bar. This week keeps the snapshot's week when you switch (the nights since it was pulled stay in the score so far); the opponent becomes the new team's from the season schedule. Snapshot files (`*snapshot*.txt`) are committed, so `git pull` brings them to your other computers.

When the file lists free agents, those are used, with roster % and "claim by" dates in Waivers. Otherwise free agents are the best players nobody rosters.

### Connect your Yahoo league (needs approved API access)

1. Go to https://developer.yahoo.com/apps/create and make an app:
   - API permissions: **Fantasy Sports → Read**
   - Redirect URI: `https://localhost:8080`
2. Create a file called `.env` in this folder:
   ```
   YAHOO_CONSUMER_KEY=your key
   YAHOO_CONSUMER_SECRET=your secret
   YAHOO_LEAGUE_ID=12345
   ```
   The league ID is the number in your league's URL (`basketball.fantasysports.yahoo.com/nba/12345`).
3. Run `python yahoo.py`. The first time, a browser window asks you to log in and approve the app. The token is saved to `.env`, so you only do this once.
4. Restart `python app.py`, or hit **Refresh** in the app.

`python yahoo.py` saves your league to `data/league.json`: scoring settings, every roster with injury status, and the top 100 free agents. Run it (or press Refresh) whenever rosters change.

### Turn on the AI GM (optional)

Nothing to set up if Claude Code is installed and logged in: the chat runs `claude -p` on your own login, no API key. It uses whatever account `claude auth status` shows, and its usage counts against that plan's limits. Answers take 10–30 seconds. Its sessions show up in Claude Code's `/resume` list for this folder.

The AI GM tab has three settings, saved in your browser: **Model** (Opus 5.5, or Fable 5.1, which needs usage credits on a Pro plan), **Effort** (Medium by default; higher thinks longer and uses more of your plan) and **Web search** (on by default: it can look up injury, role and trade news the model can't see, and names its sources, but every number still comes from `model.py`). They only apply to the `claude -p` chat, not to `ai.py`.

**History** on the AI GM tab lists past conversations, newest first. New conversation keeps the old one there. Click one to reopen it and keep going (Claude resumes that session, so it remembers), and **Delete** removes the open one. They're saved in `data/chats.json` on your Mac, so every browser sees the same list, and `data/` isn't in git.

With `ANTHROPIC_API_KEY=sk-ant-...` in `.env` (key from https://console.anthropic.com, billed separately), it uses `ai.py` and the API instead. Everything except the chat works without either.

## Workflows

### "Who do I pick up / drop?"
**Waivers** tab. Every free agent is tried against every healthy player on your roster. **Suggested moves** shows the add/drop pairs that raise your win % the most. Injured players are never suggested as drops, and neither are trade chips (players the market ranks in the first 8 rounds, top 96 in a 12-team league): when the best drop would be one, the move takes the next one and says to sell him instead. The waiver moves trades and Strategy are scored on top of never drop a chip either. An injured free agent can be suggested as an add when ESPN has him back soon: he counts for the games after his return, at his plays %. With a free IL slot (mchc lets you add an injured player straight to IL) he goes there with no drop ("IL slot, no drop"), and that's how the moves under trades count him too, for your team and, with **Count their waiver moves**, theirs; your full IL slots mean that doesn't apply to you until one frees up. Tick **Healthy only** (top of the tab, remembered in this browser) to leave free agents who are out, on IL or suspended out of the suggestions, This week's streams and add plan, and the waiver moves trades and Strategy are scored on top of. The top 3 moves also show on **My team** under "Worth doing now". **Recently dropped** lists the players let go in the snapshot's transactions that nobody has picked up since, newest first.

**Try a move** (top of Waivers) scores any add and drop you pick, like the trade builder does for trades. Type any free agent, pick one of your players (or **Pick for me**: your open spot if you have one, else the healthy player you'd miss least; players in IL slots are marked), optionally the day to make it on (**Best day** by default), and press **Evaluate move**. **Try** on a suggested move, a free agent or a drop candidate loads it in. You get a verdict (Worth it, Toss-up, Not worth it), the change in your season win % and projected finish, the change in this week's win % against your opponent (with his games left this week against your drop's, your lineup's starts before → after, since an add whose game lands on a full day can bench someone, and the expected score), and each category's odds for the season and this week, before → after. Punted categories dim. It's scored on today's roster, the same way as Suggested moves, not on top of them, so the best suggested move scores exactly what that list says. IL slots work as in Yahoo: an injured player you add goes into a free IL slot (no drop; this week he plays from his return, like a player already there), dropping a player from your IL slot doesn't open an active spot (the player you'd miss least goes too, and the note says so), and a spot a move leaves open stays open, since filling it is another add. A waiver claim counts this week only from the day it clears. This week's number is for the move made on its best day (the note says when, and how many games your drop starts first). It also says how many adds you have left this week; with none left the move waits until Monday, so only the season number counts. A move that helps this week but costs you over the season is flagged as a stream. This week's number needs an opponent: pick one on This week. The URL updates to `#waivers?add=A&drop=B`, so you can bookmark a move. CLI: `python model.py move --add "A" --drop "B" [--vs "Team"] [--day 2026-10-30]` (`--day`: make it that day instead of its best one).

### "Where do I stand?"
**My team** shows your projected finish and your win %: the share of categories you'd win in a typical week (see "The 9-cat matchup model" for One Win leagues). It also shows your odds in each category and your head-to-head odds against every team, plus your chance to make the playoffs. Under your roster, when players in your IL slots are coming back, it says who to cut once they're back: every way to keep 13 of your active players plus them is tried on your build, with what cutting the lowest-rated players instead would cost (Nov 3: cut Collins, Washington and Anthony Black, not Keegan Murray, +0.2 win %, since you're heavy on guards). **League** shows projected standings for everyone and the **Playoff race**: each team's record so far, its expected final record, and its chance to make the playoffs (top 8 of 12) and win the title (three one-week rounds, reseeded each round, the higher seed winning a tied week). The odds come from playing the rest of the season out thousands of times: the snapshot's records, this week's score so far plus the rest of the week, then every week on the schedule, each from the real NBA calendar: every player's games that week (none before an injured player's return date), so the All-Star break, the 14-day weeks 7 and 17 and the playoff weeks (Mar 22 – Apr 11) count as many games as your players really have. Replaying 2025-26 that way cut the playoff odds' error 6% (11% from the first six Mondays) and the title odds' 3% against average weeks. Each simulated season also lets every team run above or below its projection for the whole season and in single weeks, by as much as real teams did in 2025-26 (`python backtest.py playoffs`). Without that, teams' final category totals would spread about half as wide as they really do (2.6x too narrow from opening week, about 2x mid-season), and teams a naive simulation gave 80–90% made the playoffs only 72% of the time.

### "What's the news?"
The **News** panel on My team lists ESPN's fantasy news (Rotowire's blurbs) on your players and their NBA teammates who play 10+ minutes. It covers the time since your snapshot, or at least the last two days, and tags items that came out after the snapshot as **new**. Your players come first. Teammates show five items, with the rest behind a toggle. A player's card shows his three latest items. News never changes a number by itself: the model reacts through return dates, minutes and expert projections, and the AI GM can search the web for the rest. ESPN's player list (ids and the time of each player's latest news) refreshes every 3 hours, and a player's news is fetched again only when that list shows something newer (`data/news.json`). `python model.py news` prints the same list.

### "How's my matchup this week? Who do I stream?"
**This week** tab. Pick your opponent once (it's saved until the week ends on Sunday). You get the expected score (categories won–lost), your chance to win more categories than you lose (the categories move together: a team that gets more games or minutes than expected tends to win points, rebounds, assists, threes, steals and blocks at once and lose turnovers, so a lead across several categories is less safe than nine separate odds say; replaying 2022-23 to 2025-26, weeks called 10–20% were won 17–19% of the time with the categories counted separately and 15–17% now; it only touches what's left of the week, so a banked lead stays banked), each category's projected total and odds with a call (*Safe*, *Chase*, *Lost*), and **Streaming adds**: free agents ranked by how much they raise this week's win %, with games left, who to drop, the best day to make the add (your drop plays his games until then: drop a player after his Wednesday game, add the streamer for Thursday on), and what keeping him does to your season-long win %. The league allows 4 adds a week, so the panel says how many you have left: the higher of the snapshot's count and the adds and waiver claims in its transaction log since the week started (trades and drops don't count; moves made after the snapshot aren't seen). Under it, the best way to spend them: the streams by day, each scored on top of the days before, where a later one can replace an earlier streamer once his games are used. With one add left it names the day to save it for. The last add only goes on a move worth more than keeping it for late news: a player who's playing gets ruled out for his next game about 7% of the time (more if he often misses games) and about 4 in 10 of those miss the rest of the week (2022-23 to 2025-26 box scores), so an add kept back is worth that chance for each of your games left times what a stream into his games wins then. When the move is smaller, the plan says "Keep your last add for late news" with both numbers. With none left there are no streams until Monday. Projections count each player's games left this week, but only the 10 best players with a game each day who fit your starting slots by position (PG, SG, G, SF, PF, F, C, C, Util, Util; Yahoo scores starters only, so a bench player's game counts on a light day or when a starter sits, and a third center can sit even with a guard spot open). Each game counts the player's chance of playing it (lower the night after another game: on the second night of a back-to-back the 156 best players sat 13% of the time against 6.5% otherwise, 2022-23 to 2025-26, and the players who miss the most games sat a quarter of them), and when one of the 10 sits, the next player with a game who fits takes his slot, as you'd swap him in. Replaying the real league's past days (each snapshot against the next one's games played), days with someone on the bench came out 3% low, where they were 10% low before bench players filled in. Games left shows the same count. When the snapshot has them, Yahoo's own games left (and games played so far) show next to it. Yahoo counts the lineups as they're set now, so its number is usually lower. Players in IL slots sit until they're back (their return date, or the game ESPN lists them probable / questionable / doubtful for), then start in place of who's cut: for you, the player My team's cut plan names (with returns days apart, whoever has the fewest games left then), for the other team its weakest player, an open spot first. **Coming back** is uncertain, and so are the first games: ESPN's return date is a guess, mostly the game after the one he's ruled out for, and this season players it listed out until a date played their team's first game from it 24% of the time, the second 39%, the third 63% (the model had counted about 67% each). So each game from ESPN's date counts at the chance he's back by then: 38% for his first, 62% by his second, 76% by his third, times his usual chance of suiting up, for a player ESPN lists Out. One it lists Day-To-Day is back sooner (60%, 84%, 94%: this season those played their first game from the date 45% of the time, Out players 23%) and takes his spot from his first game (a probable / questionable / doubtful listing for the game counts as that instead). Whoever he replaces stays until he's likelier back than not, his second game from the date, since you'd only drop someone once he's active: Ingram, back Sunday with one game this week, replaces nobody this week. His first games back also count short: replaying 2022-23 to 2025-26, a player who missed 1–2 games put up 96% of his usual line in his first game back, 3–5 missed 91%, 6–10 86%, 11–20 78%, and 21 or more 71% (still about 73% in his third game, 82% in his fourth), minutes restrictions and rust. Those count in the odds, streams and Start / sit, not in Games left (`python backtest.py returns` measures both). Season-long numbers count from the return date as before: a game or two out of a season barely moves them. Another team's open spot is streamed from tomorrow (while it has adds left) by the best-scheduled of the top 5 healthy free agents, until a player back takes it; yours stays empty, so Waivers tells you to fill it. The panel says who's back and for whom, and a stream that drops a player being cut anyway is cut in his place (the plan shows "until" that day). A waiver claim counts only from the day it clears. A snapshot with a matchups section (or a Yahoo pull) fills in the opponent and the score so far, and when it was pulled after that day's games started, the rest of the week counts from the next day, unless the file says its totals stop before the first tip-off (then tonight's games still count). Without one, totals start at zero (right on Mondays). **Games under way** (nba.com's live scoreboard and box scores): once a game tips off, its players are locked as Yahoo locks them. Their live stats go on top of the score so far for each team's starters. On the day the snapshot was pulled that's the lineup the snapshot shows: Yahoo only scores starting slots and never subs a bench player in, so a benched player's game counts nothing, and a starting slot left empty at the pull goes to the team's best bench player who plays (managers fill one). A team with no starter set at all hasn't set its lineup, and banks nothing that night (John Ball, Nov 6 and 7). Pull the snapshot before the first tip-off and after you set your lineup. On a later day the snapshot's lineup is stale, so it's whoever the best per-game lineup would start (the lineup you really set can differ). A finished day the snapshot missed counts the same way, so the score doesn't jump at midnight. Replaying the five nights with a snapshot pulled before tip-off (Oct 27–30, Nov 4) against the next snapshot's totals, the snapshot's lineup cut the error by almost half against the per-game guess (576 vs 1,071, summed over teams and stats; your Nov 4 came out exact, where the guess counted Saddiq Bey over John Collins); most of what's left is managers changing their lineup or adding a player after the pull (`python backtest.py lineups`; on eight nights to Nov 7, 1,076 vs 2,038). The subtitle says how many games are under way, final and still to come, with the time of the scores. Start / sit leaves a locked player alone (**Locked** in the day's lineup; the later games fill the slots left), streams and Try a move don't count his game as one left, and a move that drops him waits until tomorrow, since Yahoo won't drop a player whose game has started. Last night's late games keep counting from the live box scores until the NBA's own box scores have them (refetched once a game goes final, not on the 12-hour clock). Replaying Nov 2 from the 5:31 PM snapshot (totals frozen before tip-off), the live score after the night matched the next morning's snapshot exactly for 3 of 12 teams with the per-game guess, 11 of 12 with the snapshot's lineup. Once the snapshot's week is over, the season schedule in the snapshot names the next opponent and the week's dates (weeks 7 and 17 run 14 days) until a new snapshot brings the score. **Start / sit**, under the categories: each day left, who starts for the most category wins this week. It tests every sit, start and swap against this week's odds and keeps the best one until none helps. A close category counts and a safe or lost one doesn't (a punted one counts like any other: This week runs on your real odds), so it can start a shot-blocker over a better player when BLK is the swing category, and it can sit someone with a spot open when his game hurts more than it helps (a bad shooter while you lead FG% narrowly, turnovers in a close TO). A bench player still fills in when a starter sits, except one sat on purpose with a spot open, and nobody replaces a starter whose game has tipped off. **Play for** picks the categories to chase: all of them (the default), or only the ones you choose, with what that costs the rest. Each day's row shows who sits, what changes against starting your best per-game values, and the category odds it moves. Pick a day to see its lineup in Yahoo's slot order (PG, SG, … Util, then the bench; a slot nobody with a game that day can play shows as Empty, and the count counts it) and, for every player, his chance of playing that game (red under 70%), the boost he gets from teammates out that day (who, and whether it's short-, medium- or long-term), and what changing his call would do and who he'd swap with. Injuries count both ways: a player's own injury odds and return date, and the extra minutes and shots from teammates who sit that day. CLI: `python model.py week --vs "Team"`, or just the lineups with `python model.py lineup [--cats "FG%,TOV"]`.

### "When should I stream? Whose schedule is heavy?"
**Schedule** tab. **Games per day** is a calendar of the rest of this matchup week and the next three (a 14-day week takes two rows): each day shows how many of your active players have an NBA game. Only 10 start, so a red day has more than that (the number that sit) and a green day has open starting spots a streamer would fill. Pick a day to see who starts and who sits: in a week with a known opponent, the ones who add least to your odds against them (as in This week's Start / sit), else your lowest on your build's value, so punts count. The week totals show starts, games lost to a full lineup, and open spots, and the week's label shows your adds left (4 a week; a picked day with open spots warns when you have none left). **Your players** lists each one's NBA games per week, with a red number for games he'd sit because 10 better players have one that day; the rows add up to the calendar's Starts and Sit (a player back from an IL slot this week has a row for it, and a game already under way counts on neither). **NBA teams ahead** ranks all 30 teams by games over those four weeks, plus the fantasy playoff weeks (21–23, read from the snapshot's settings), your players on each team and the best healthy free agent there for your build. Switch to **On your open days** to count only games on days you have an open spot: that's how many games a streamer from that team would actually start for you. Counts use today's roster, players in IL slots sit (this week: until they're back, in place of who's cut, as in This week), injured players count from their return date, and starters fill your slots by position, so a player can sit on a day with a spot open when no open slot fits him (the day's line then says which positions a streamer needs). The NBA teams' open-day counts don't check a streamer's position. CLI: `python model.py schedule`.

### "Should I punt something?"
**My team** shows your odds in each category. Categories you win under 35% of weeks get a **Punt …** suggestion. You can also toggle any category with the **Punt** chips in the top bar; the button and the chips both reload every view built on your punt (This week, Schedule, League, Compare, an open trade or Try a move), Strategy aside. A punted column greys out in every table, and trades, waivers and ideas re-optimize with that category treated as a loss. This week is the exception: Yahoo scores the matchup on all nine categories, so its win odds, streams, plan and Start / sit use your real odds in every one, a punted one included. There the punt only changes what lasts: the Season column, and who you'd cut when a player comes back from an IL slot (on a TOV punt that plan cuts Bey and Collins instead of Black and Collins once Ingram, Suggs and Murray are back). Win % numbers scored that way say so ("FT% counted as lost"); My team's header and the trade's Standings movers show your real odds.

Toggling a chip always lowers today's number, because it concedes a category without changing your roster. A punt only pays off through the moves it unlocks. The **Strategy** panel on My team tests that: **Compare builds** tries staying balanced, every single punt and six common pairs (FT%+TO, FG%+TO, FG%+FT%, AST+TO, 3PM+FT%, FG%+3PM). Each build makes its own waiver adds, then up to three fair trades in a row. Each trade is the one that helps that build most, searched with its punt on the rosters the trade before left, and each clears the fair tier on its own. A punt usually pays off over several moves, and the first one costs the most, so a plan's first trade may lower your real odds before the next ones pay it back. Every step is scored on your real odds, with nothing conceded, and a build keeps its best stretch of the plan (0 to 3 trades). The verdict says "Stay balanced" unless a punt's plan beats staying balanced by more than a toss-up. Each build also shows your **playoff and title odds** after its plan (the same season simulation as My team's playoff race). The playoffs are one matchup a week, won on 5 of 9 categories, so a build that's strong in five can win more playoff weeks than its share of categories says. When a build's title odds beat the verdict's by 2 points or more, a **For the title** line names it. On Nov 7 that was punting FG%: 30.8% to win the league against 23.6% staying balanced, though it wins fewer categories over the regular season (60.3% vs 61.6%). Against the likely playoff teams its playoff weeks are won 75.6% of the time, against 67.8%, with categories allowed to move together as This week counts them. Staying balanced also tries every trade the other builds found and repeats each build's plan for as long as every trade still lifts your real odds. So a punt only wins through moves it alone unlocks. Pick a build under **Every build** to see its plan step by step: waiver adds, each trade with the waiver moves it leads to, your win % after each step, and **Load** to open a trade in Trades. Load is greyed out on a trade that needs the earlier ones first. Each punt also shows its **star fit** (your top five players' weak spots it concedes, e.g. Jokić's TO) a **buy list**: players on other teams the market prices furthest below their worth to that build, since Yahoo's ranks count every category. The **sell list** is its mirror: your players the market prices 5 or more above their worth to the build, each with why (Yahoo projects him higher than we do, a hot start, games he'll miss, or his value is in what the build punts), and **Find buyers** to shop him in Trades. It takes about 15 seconds. CLI: `python model.py strategy [--size 2]`.

Under the category odds, **Cheapest to move** lists the three categories where one more z (a player's category cell going up by 1.0) raises your odds most. That's where a trade or stream pays most. Odds near 50% move most, but noisy categories move less than their odds suggest.

Classic pairings: big men punt FT%, high-usage guards punt TO, wings punt AST.

### "Is this trade good?"
**Trades** tab: check players under *You give*, pick their team, check players under *You get*, then **Evaluate**. You see:
- **Your win %**: before → after, with both rosters updated. If you take back more players, you drop your weakest; if you send more, you pick up the best free agent. So 2 scrubs for a star scores correctly.
- **Compared with waivers.** Your number starts from the waiver moves you could make without a trade (the note under the verdict names them, e.g. "Nikola Vučević for Precious Achiuwa (+1.2%)"), so a 2-for-1 gets no credit for a pickup you'd make anyway: its open spot gets the next-best free agent. The finder works the same way. Untick **Count my waiver moves** in the finder toolbar to score deals on your roster as it is today, as if you make no pickups. The other team is judged on the trade alone, since that's what managers look at. Tick **Count their waiver moves** to measure them against their own waiver moves too. Both are remembered in this browser. Their side drops players too: if a deal leaves them more active players than spots, they drop whoever they'd miss least (never a player in an IL slot), and the note under the verdict names him.
- **Players back from your IL slots.** Both numbers assume you cut the best players once they're back (every way is tried, as in My team's Roster panel). The note under the result names them, e.g. "When Ingram, Suggs and Murray are back: now you'd cut Black, Gafford, Collins; after this deal Collins, Bey, Murray." With no punt, your row in the standings table counts the same cut, so it matches the win % above it (with a punt the table is real odds and the win % is on your build, so they differ anyway).
- **Them**: their win % before → after. A trade can help both teams when the categories fit.
- **Market**: how managers would price it, from Yahoo's ranks (see "Market value" below): what you send and get in market value, and a verdict like "you overpay 35%" or "even". **Will they say yes** reads mostly off this. The note under the verdict says how the deal looks on this season's hot and cold starts alone.
- **Projected finish**: your league rank before → after.
- **Playoff odds**: your chance to make the playoffs before → after, and your partner's (the League tab's Playoff race, rerun on both new rosters), and **Title odds** from the same run. Shown once the snapshot has the season schedule. Worth a look when a deal pushes a rival over the cut line.
- Your odds change in each category.

**Copy offer** copies the offer and a short pitch for the note on Yahoo's trade offer, built from the numbers (their weak spots it shores up, categories it adds, the market when it favours them, roster spots they free). It never claims more than that. **Ask AI GM for a pitch** writes a longer one in the chat. **Save trade** keeps it for comparing later.

## How the numbers work

**Player lines (the projection).** Every player has a rest-of-season per-game line. The pre-season baseline blends the last two seasons (a game in 2024-25 counts half as much as one in 2025-26) and is pulled toward a fringe-rotation line by 25 games, so a 5-game season isn't taken as gospel and a player back from a lost season isn't treated as a rookie. The line then shifts toward this season as games pile up, in two parts: minutes per game × production per minute. Minutes move fast, `GP / (GP + 3)` (half after 3 games, 77% after 10), because a new role or team shows up at once and sticks. Production per minute moves slowly, by minutes played against 20 games of baseline minutes (13% after 3 games at his usual minutes, less if he barely played), because 3 games of shooting is noise. Since Nov 6 each stat moves at its own pace, as measured on 2022-23 to 2025-26: shot attempts and assists faster (5 and 15 games), steals slower (60), and FG% and FT% slowest, counted in attempts (40 and 60 games of his usual attempts), with points built from the shooting. A career 80% free-throw shooter who starts at 60% on 5 attempts a game projects 77% after 10 games (73% before): shooters who start 5+ points off their normal kept only 1–25% of the gap the rest of the season. Veterans' pre-season numbers also move with age, 0.75% of production a year either side of 27 (a 33-year-old 4.5% under, a 22-year-old 3.75% over). So a starter who lost his spot drops fast, and a bench player who got 8 minutes a night barely moves his per-minute numbers. Replaying 2025-26, this cut the error of each Monday's rest-of-season lines by 8% in the first six weeks (10% for players whose minutes changed), and the matchup backtest improved slightly. This season's games don't all count the same: each one weighs half as much for every 45 days since it was played, so a player's last month says more than his first. Replaying four seasons (2022-23 to 2025-26, `python backtest.py recency`), that and the faster minutes (3 games, was 6) cut the rest-of-season error about 1% over the season in each one (rerun Nov 4; it was 2% before the bench and rookie lines improved underneath it). Letting minutes move a little slower (4 games) is now a hair better over the season, but it makes the weekly matchup odds worse in three of the four seasons, so This week stays at 3. Since Nov 7 the season line (trades, standings, Waivers' season column, Strategy, the playoff race's later weeks) is a separate line with slower minutes, `GP / (GP + 6)`: over a season an early minutes jump fades about halfway, while next week's minutes follow last week's. Replaying four seasons (`python backtest.py season`), the season line's error fell 1.9 / 0.3 / 3.1 / 2.0% (2022-23 to 2025-26, with the netting change under Teammates' injuries), and the playoff-odds backtest is the same or a hair better (title odds 0.2771 → 0.2750 log loss). P.J. Washington, at 33 minutes with Dereck Lively out all season so far, comes down from 33.2 to 32.5 minutes over the season and stays at 33.2 this week. Weighting the last week or two much more was worse (+5.5%): hot and cold streaks don't last. Treating an established player's early minutes dip as temporary (counting drops slower than gains) didn't help either. Rookies nobody projects start from a fringe-roster line's per-minute numbers at 12 minutes a game, so three hot games don't make them stars. A player no expert projects at all (deep bench, two-way, undrafted) has the fringe part of his baseline at 12 minutes too, not the fringe line's 26: replaying 2022-23 to 2025-26 (`python backtest.py bench`), those players ran about 2 minutes a game high in the first six weeks, and the change cut the rest-of-season error 2% for everyone (6% for them) in every season. Felix Okpara (one game, one minute) projected 20 minutes a game before it, 9 after.

**Expert projections.** The pre-season baseline is blended with an expert projection, weighted 60% expert, 40% box scores. The expert line is Yahoo's rest-of-season projection from the snapshot (Part 8: rostered players and the top 100 free agents) and ESPN's season projection for everyone else (fetched daily, each day's copy kept in `data/projections_<date>.json`). Yahoo shows no minutes, so its minutes are ESPN's (or ours) scaled by how much more or less Yahoo has the player scoring, rebounding and assisting: a projected role change moves minutes, not per-minute rates. A Yahoo line under half of ESPN's (points + rebounds + assists) isn't a real per-game line, so ESPN's is used instead: some of Yahoo's rows look like they have missed games baked in (Jaxson Hayes at 1.7 points a game while playing 27 minutes). Where ESPN has no line, a Yahoo line under half of the player's last two seasons or of this season (3+ games) is dropped the same way, and he's treated as a player no expert projects (Kobe Sanders: Yahoo 1.9 points a game, 11.0 this season, now 7.9 rest of season instead of 7.0). Checked on the Oct 26–31 snapshots against the games after each: those players' error fell 2%, nobody else's moved. A rookie's baseline is the fringe line, so a rookie with no games yet (AJ Dybantsa) still gets a projection-based line. For a rookie the expert projection weighs 75%, not 60%, and his per-minute production follows this season twice as fast as a veteran's (10 games of his minutes, not 20), since he has no NBA past to lean on: replaying 2022-23 to 2025-26 (`python backtest.py rookies`), that cut rookies' rest-of-season error 0.5–5.5% in every season (Cameron Boozer 15.8 → 16.6 points). The projection alone was worse in two of the four seasons. Yahoo updates its projections during the season (Darius Acuff 17.3 → 23.3 points in a week), so they partly repeat what the box scores already say. Freezing each player's Yahoo line at the first snapshot that lists him was tried and made this season's lines worse (`python backtest.py yahoo`: players whose Yahoo line moved missed by 0.55 frozen against 0.53 live), so the live line stays; there are no Yahoo projections from past seasons to check it further. The 60% comes from replaying 2025-26 with ESPN's preseason projections: each Monday's rest-of-season error fell 5% at the start of the season, 3% in weeks 1–6 and 2% over the season (top 200 players: 7%, 3% and 2%), and 6% for rookies in weeks 1–6, who before had no line at all until their first game. This season's games then take over as usual, so the expert part fades as games pile up. The player card shows which projection went in.

**Plays %.** The share of games a player is expected to suit up for. It comes from games played in the better of the last two seasons and this season so far (out of his team's games: Phoenix had played 3 when others had played 6), pulled toward 70%, then cut by the injury tag if he sat his team's last game (GTD 91%, O 80%, INJ or IL 70%: what players who'd sat played over 2022-23 to 2025-26). An expected return date of today cuts nothing. A tagged player who played his team's last game isn't cut. When ESPN's injury report has an expected return date, that replaces the tag: the player counts for the share of remaining games after that date. A rest day (ESPN's note says he's rested, often the second night of a back-to-back) shows as a grey **REST** tag, not O: he misses that one game and is otherwise treated as healthy, even when Yahoo tags him O. Missed games are half-covered by a waiver-level fill-in, the way a bench player or streamer would cover them. The rule was fitted on 2024-25 and 2025-26 and holds on 2022-23 and 2023-24 (`python backtest.py availability`): for players who are playing now, past games played barely predict how many of the games left they play, and the worse of two past seasons adds nothing. So one lost season isn't treated as fragility, a game this season counts five times a game in the better past season, and an iron man and a player who keeps getting hurt end up closer than you'd think (about 79% vs 65% early in the season). It guesses games played 13% better than the old formula (36% better for players back from one lost season), and the matchup odds improved too.

**Wk.** Games left this week (Monday to Sunday) from the NBA schedule, counting only games after a return date. `League.week_vec()` turns that into this week's expected totals. Over a few days a player who played his team's last game suits up more often than his Plays %, because injuries come in spells: over 2022-23 to 2025-26 those players played 89–91% of the next week's games, against 76–78% guessed. This week counts each of his games on its own: his next one at the chance he isn't newly ruled out before it, each later one a little lower, from the same late-news rates the add plan keeps an add for (those seasons, from any day of the week: 93% of next games played, then 89%, 87% and 86%; the model is within 2% of each). Until Nov 4 every game this week counted the same 90%, so tomorrow's game ran low and the weekend's high (M27). The backtest's weekly totals land within a few percent. Trades and the season-long odds still use an average 3.4-game week.

**Injury news.** ESPN's public injury report (every 30 minutes while the app runs, else every 3 hours) adds the latest note and the expected return date. Hover an injury tag to read it. When the note lists a player for one game the way the NBA's injury report does (probable, questionable or doubtful for Wednesday's game), that game counts at how often players listed that way have played it this season: probable 92%, questionable 48%, doubtful 10% (104 games from Oct 28 to Nov 2, `python backtest.py gameday`; 215 games to Nov 8 gave 91%, 49% and 14%, so they stay), and his tag reads **Q Wed**. It moves This week, Start / sit, streams and Try a move; one game doesn't move the season numbers. The league's own tag wins when they disagree, except when ESPN's report, fetched after the snapshot was pulled, no longer lists the player: then Yahoo's tag is out of date (a rest day the snapshot caught, a player since cleared) and doesn't count.

**Teammates' injuries.** When a regular (25+ minutes a game) is out with an expected return date, his teammates play more until he's back. A player with no game this season and no injury listing (Russell Westbrook, unsigned) isn't counted as sitting out: he used to take up to 9 minutes a game off his old teammates' lines. Half his minutes go to teammates who play 10+ minutes, split by how much room each has under 36 minutes (nobody goes past it), with about twice as much going to players in a similar role (by assists, rebounds, blocks and threes per minute). When two or more are out at once, which is most weeks a regular is out, their minutes go to the players left, never to each other, in stretches until each one returns. Who gets them also leans on what really happened this season: in the games a regular sat, a teammate who took his spot (Jeremiah Fears went from 23 to 30 minutes in the two games Dejounte Murray missed) gets more of his minutes than the general rule would give him, counted as if the rule were worth 4 games of evidence, so a couple of games move it partway. Only minutes learn from this; a couple of hot shooting nights are noise (letting the split move per-minute production too made lines no better on four seasons, `python backtest.py rates`). They play those minutes at their own rates and also pick up a quarter of the shots, points, assists and turnovers those minutes don't replace. The rest goes to the end of the bench. The lift only counts for a player's games before the return date: all of them in This week, and their share of the rest of the season in the season-long line. This season's box scores already include games where a teammate sat, so they're read net of what each player picked up in those games. That way the boost isn't counted twice, and it goes away when the injured player returns. This week takes off all of it. The season line takes off half (since Nov 7): regulars keep missing games all season, which their availability already counts, and their backups keep getting those minutes, so taking off all of it left season lines low (taking off none was worse in 2023-24). LaMelo Ball's season line went from 27.7 to 29.0 minutes. A player out since before the season was already in the preseason projections, so his teammates' lifts are cut by the part of their line that comes from those. A star's minutes spread over a whole rotation, so most lifts are small: LaMelo Ball gets +1.0 min and +1.4 pts a game while Anthony Edwards is out (back Dec 21). Player tables tag a lift of a minute or more with how long it lasts: **short-term** when the teammate is back within a week, **medium-term** within a month, **long-term** after that (the biggest lift's, when there are several; hover the tag for each one, with points). The player card lists every one with its term. Start / sit uses each game's own lift: a player whose teammate returns Saturday gets the boost on his games before Saturday only, not spread over the whole week. Replaying 2025-26 (`python backtest.py teammates`), next week's minutes error falls 3.1% for players with an injured teammate who played all their team's games that week (2.4% before teammates out together were spread together), and 3.6% on 2024-25, which nothing was fitted on. Each team's own split cuts it another 2.9% on 2025-26 and 4.3% on 2024-25 (`python backtest.py onoff`). The player card shows the evidence: "This season without him: 30.0 min, 21.0 pts in 2 games; with him: 23.0 min, 9.0 pts in 4 games."

**Value (the table columns).** z-scores against the top `teams × roster` players by minutes. FG% and FT% are weighted by volume, so a 60% shooter on 2 shots barely counts, and TO counts against you. This is the quick player-ranking view.

**The 9-cat matchup model (what the advice uses).**
1. Each team's expected weekly totals = Σ players' per-game lines × 3.4 games × their Plays %.
2. For every pair of teams and every category: the chance team A beats team B that week. This uses the gap between their totals and realistic weekly randomness (box-score noise, schedule swings, shooting variance on actual attempts).
3. What the week is worth in the standings. **Head-to-Head Categories** (the default, and Yahoo's): every category counts as a win or loss, so it's the expected share of categories won. **One Win**: only the matchup counts, so it's the chance of winning more categories than you lose (5 of 9). The format comes from the snapshot's `Scoring type:` line or Yahoo's `scoring_type`.
4. **Win %** = average of that against every other team: your projected standings win %. **Projected standings** rank every team by it.

Category win % moves about 2.5× less than One Win odds per move (a +2.7 trade there is about +1.1 here), so the cutoffs (trade tiers, verdicts, waiver moves) scale with the format (`CAT_SCALE` in `model.py`). Projected standings run tighter too: about 41–57% on the real league.

A trade, add or drop is judged by how much it changes your win %, with both rosters updated: extra players get dropped (whoever the team would miss least, never a trade chip while anyone else can go: Yahoo has the manager pick the drop, and nobody cuts a top-96 player; a deal that only fits by cutting one is flagged, and Find trades leaves it out), open spots get the best free agent. IL slots count as in Yahoo: an injured player you get goes into a free IL slot, and sending away a player from your IL slot doesn't open a spot. A player sitting in an IL slot counts only for the games after his return. He takes an open roster spot if the team has one, else he replaces the team's weakest active player (if he wouldn't beat him, he's the one cut and counts for nothing). Until a returning player fills it, another team's open spot counts as a waiver-level pickup, since its manager can stream it; yours counts as empty, so Waivers tells you to fill it. Without that, Shanghai's two open spots (two IL players dropped, three parked who are back two days later) read as empty all season and dropped it from 2nd to 11th. Your side of a trade starts from your free moves: the best add/drop (or plain add into an open spot), repeated while one still raises win % by 0.2 or more (0.5 in One Win). Waivers lists yours. This is what makes it account for:
- **Your strengths and weaknesses.** Extra rebounds barely help if you already win REB 90% of weeks, and they help a lot if you're at 50%.
- **What everyone else has.** Odds are computed against every real roster in your league.
- **Punting.** A category you can't win stops mattering on its own. The Punt chips make it explicit: punted categories count as automatic losses, so the advice optimizes for the other categories.

**Now / How it looks to them.** The same line with production per minute weighted harder toward this season (10 games of baseline minutes instead of 20: 23% after 3 games at his usual minutes). For trades, a player's look is counted over the games he actually plays (managers remember who missed a season) and never below what the best free agents look like. A manager taking back extra players feels the loss of the players they'd drop. Trades show it as a note (Hot & cold runs on the last 14 days instead).

**Market value (Mkt).** What other managers pay for a player comes from outside the model: Yahoo's preseason rank blended with its current (season-to-date) rank, the current one weighted `GP / (GP + 20)` because it's noise early (injured players sink to 600+), blended as a geometric mean so a cold start costs a player as much as an equally hot one gains, then re-ranked. Four cold games no longer sink Jalen Brunson (#27 preseason) behind a hot Paul George (#75): they read #35 and #59. A player Yahoo hasn't ranked uses the model's own rank, marked `*`. Value = `100 × 0.97^(rank − 1)`: rank 1 = 100, 25 = 48, 50 = 22, 100 = 5, 150 = 1, so a star is worth more than the sum of spare parts. Players traded together count as a package: the best one in full, each next one at 70% of the one before (100%, 70%, 49%), because managers pay extra for the best player in a deal and need roster spots for the rest. So three players for one star cost more than their market sum, a 1-for-1 is priced as before, and a throw-in barely counts. At 70%, a 2nd-round plus a 3rd-round player is about even for a 1st-rounder, the usual rule of thumb. A trade's market counts roster spots: the side taking more players loses the market value of the ones it drops, and each open spot the other side fills is worth the waiver level (about 1), whoever fills it: a free agent is free, so a pickup never makes a deal look richer. Trade tiers and "Will they say yes" run on it. Deals show both: **Market** is the plain sums and **Package** the same deal counted as packages, which is what "Will they say yes" reads (they match on a 1-for-1).

**Points leagues** use the league's scoring weights and per-game values (no matchup model).

**Honest limits:**
- The weekly-randomness settings are fitted to real 2025-26 box scores (`python backtest.py`: 20 simulated leagues, each week predicted from what was known that Monday, with injured players sitting until a rough guess at their return). Category odds come true at the rate they say, within a few points (what a categories league runs on); This week's whole-matchup odds within about 1 point on average since they count the categories moving together (M9: 1.3–2.2 points before, too sure at the edges; `python backtest.py corr`). Still, read 55% vs 58% as "about the same".
- The market curve (`MARKET` in `model.py`) and the tier cutoffs are starting guesses. There's no data yet on which offers real managers accept.
- Not modelled yet:
  - positions in the season-long numbers (trades, waivers, standings): only This week and Schedule fill slots by position. On the real rosters it costs 0.0–0.1% of games beyond the 10-starter cap, but a roster with no center loses about 6%, so a trade that leaves a starting slot nobody can fill is flagged instead
  - the real schedule in trades and win %: they use an average 3.4-game week by design (This week and the playoff and title odds use the real one)
  - Yahoo's tiebreaker for equal records: the playoff odds break ties at random
  - keeper or dynasty value
- An expert projection updated after a mid-season injury (Yahoo's may be) can count a teammate's lift twice for its part of his line; only injuries from before the season are taken out. The randomness settings assume ESPN's return dates are roughly right (nobody has measured how far off they run yet). If ESPN's injury feed is down, the app only has Yahoo's injury tags and its odds run a little bold.

- Playoff odds: replaying 2025-26 in 60 simulated leagues from every Monday, they come true within about 3 points (teams given 80–90% made it 87% of the time). Those leagues never trade or pick anyone up, so a real season swings a bit more. Title odds can't be checked as closely, since each league crowns only one champion.

The settings live at the top of `model.py`. Re-run `python backtest.py` after changing how players are projected; it prints predicted vs actual win rates.
