# Files: what each one does, in full

The caches, the app's threads and endpoints, the snapshot import and the AI GM. Moved here from CLAUDE.md on Nov 15, 2026, word for word. **Read it before changing `app.py`, `yahoo.py`, a cache or the page's data flow.** Model maths: `docs/MODEL.md`.

- `model.py`: the engine (`League` class) plus a JSON CLI. All numbers come from here: UI, AI chat and the `/gm` skill.
- `yahoo.py`: league snapshot → `data/league.json`. Y5 (Nov 24): `lineups()` keeps every team's lineup on each past day and the season's add / drop log in `data/yahoo_lineups.json` (`{league, days: {date: {team: [[name, NBA team, positions, slot], ...]}}, moves: [{ts, team, add, drop, waiver}], at}`, ~270 KB): `teams/roster;date=D` is one call a day for all 12 teams (the same as `team/<key>/roster;date=D`, checked), a past day never changes, so only days not in the file are asked (35 calls in 3.5 s once, Oct 20–Nov 23; then one a day), and `transactions;types=add,drop;start=;count=100` with them (168 on Nov 24). Not in `pull()`: `app.live()` calls it after each 15-minute pull and it makes no call while the file has yesterday; `python yahoo.py lineups` by hand. A failed call keeps the days fetched and raises. `model.habits()` reads the days (`model.lineup_days()`, at every `load()` and `replay()`), `backtest.py habits` both. `parse_text()` also reads Part 6's "WEEK N FINAL RESULTS" block as `results` (Q33). Since Nov 24 (Y2) `pull()` gives them too: `scoreboard;week=<current_week - 1>`'s `stat_winners` counted per team (a tie nobody's) as `{week, teams, score}` plus the teams' `totals`, once the week's matchups are `postevent`, then kept from league.json (`build()` now keeps `results`, so the API's day files carry them into the history's rows; week 5 matched the Nov 23 text snapshot on all 6 matchups). Y2 also: `pull()` runs its calls `WORKERS` (6) at a time on a thread pool once the settings are in (`ask(path)`: each path once a pull), `_api()`'s `get()` gives each thread its own rauth session and refreshes a 401's token once under a lock, `RAW` files are named by path; the 20 rank pages (`_ranks()`) are reused from `data/yahoo_ranks.json` (their XML and time, ~1.7 MB) for `RANK_MIN` (60) minutes unless `fresh` (the Refresh button, `app.pull()`, and `check`), and a free agent on an hour-old page who is on a roster now is left out; `yahoo.TOOK` = the last pull's (seconds, calls). Y4 (Nov 24): the rank pages ask `out=RANK_OUT` (`percent_owned,percent_started,ownership,ranks`: one call carries all four, checked on the real league) and `player()` keeps `owned` / `owned_delta` (Yahoo-wide roster %, coverage week: the change this week) and `started` / `started_delta` (start %, coverage date: since yesterday; Yahoo leaves the value out for about 60% of free agents on a day, mostly those with no game, so it's missing then), each only when Yahoo gives a number; the cache stores `out` and one saved with another list is asked again. They're in `NEWS()` nowhere (not news), `model.YAHOO_PCT` passes them through `player()`, and `_market()` doesn't read them. Before: ~9 s, 30 calls one after another; after: ~1 s, 10 calls (2 s, 31 calls fresh). IL eligibility (Q29, Nov 24): each rostered player (one with a `slot`) has `il` = "IL" or "IL+" among his `eligible_positions/position` (in mchc exactly the O-tagged players: 29 of 29 and 25 of 25 on the Nov 24 pulls); `model._stuck()` reads it (a text snapshot has none: a tag other than O there is the fallback), and `check` prints who's in an IL slot without it. Yahoo API (read-only; Nov 23: `pull()` reads Yahoo's XML into parse_text's dict, yfpy only signs the calls with the token in `.env`; `build()` is the shared rest for both sources; `snapshot()` also saves `snapshots/yahoo-<day>.json`; `python yahoo.py check` compares a pull with the newest snapshot and saves the raw XML to `data/yahoo_raw/`; first real pull Nov 23, ROADMAP Y1; `pull()` also reads the season's trades and your pending offers (`trades`: key, status, from = proposer, to, give, get, ts) and where the league drafted everyone (`draft`: name → pick; a snapshot import keeps the last pull's); app.py's Refresh pulls when `.env` has `YAHOO_LEAGUE_ID`, `app.pull()`; a failed pull keeps the last league. Y3: `pull()` takes every rank-page player nobody rosters now as a free agent (one dropped since an hour-old page too), so the API pads nobody and every free agent has Yahoo's positions (0 of 328 padded on Nov 24, no extra calls)), `python yahoo.py import <snapshot>.txt ["Team"]` (Instinct-style league snapshot or a hand-typed list, `parse_text`; `from_text(write=False)` builds the league without touching `data/league.json`, for `backtest.py lineups`; unknown sections are skipped; snapshots live in `snapshots/` (`model.snapshots()` also sees one saved into the project folder, for the history and backtests; since Y3 the app neither files nor auto-loads them: import one by hand, then Refresh refetches injuries, stats and box scores, `load(refetch=)`); the top-bar dropdown switches your team via `/api/me`, which keeps the week's `from`, dates and Yahoo games and takes the new team's opponent from the schedule, `model.switched()`, B1), or `python yahoo.py demo` (fake league from real stats). M30 (Nov 24): settings' `trade_end` from `trade_end_date` (the API) and the "Trade deadline" line (text snapshots), for `model.dates()`; `check` compares it like the other settings.
- `model.py` also fetches the NBA schedule (`nba_api`, cached a day; since D1, Nov 24, each game's opponent from the same feed, `opponents()`, `data/opponents_<season>.json`, a day), ESPN's injury feed (cached 3h, archived per day), ESPN's projections (`espn()`, cached a day, archived per day), this season's box scores (`gamelogs()`, cached 12h, for the player card's recent lines; with this season's stats once a final game is missing from them, at most every 30 min) and live scores (`scores()`, M18: nba_api's live scoreboard + box scores of games under way or final, `data/live.json`, every `LIVE_POLL` 5 min while one is on (`live_on()`), else 30; the last two days kept; a failed box keeps that game's last one) in `load()`, and passes `news()` (ESPN fantasy news: the player list with ids and latest-news times cached 3h in `news_index()`, a player's items refetched only when that time moves) for the card and My team's News panel (`roster_news()`). News never changes a number. `League` built directly (tests) gets none of them, so it stays offline. Freshness (Q9): `SOURCES` lists those caches and their refresh windows. A failed refresh keeps the old copy and is logged in `FAILED` (this season's stats too, which only raise with no copy at all). A bad reply is a failed refresh (Nov 9): an empty JSON feed (`_cached()`; injuries and projections before their day's archive), a stats or box-score table that came back 5% shorter than the saved copy, empty included (`_save_csv()`; with nothing saved yet, before opening night, an empty one is fine). Every cache, `league.json` and the app's own files are written as a copy and swapped in (`_write()`): the app's `live()` thread, Refresh and the AI GM's `model.py` runs read them while another writes. `freshness()` reads file times against the windows (ok / stale / failed / missing); `load()` keeps the times it built from (`League.loaded`, news read live) and `state()["sources"]` feeds the sidebar.
- `app.py`: stdlib `ThreadingHTTPServer` on 127.0.0.1:8765, routes in `api()`. `live()` (a daemon thread) refetches ESPN's injury feed every `LIVE_MIN` (30) minutes and rebuilds the league on the same snapshot, and on game nights also a minute after each tip-off and every `LIVE_POLL` minutes while one is on (`model.next_poll()`; live scores refetch on their own window, the injury feed stays on `LIVE_MIN`), and drops a rebuild that started before `league.json` changed under it (`gen`: bumped by `remember()` (team switch, opponent) and Refresh, after the write; Nov 4, audit #23); This week reloads every 5 minutes while a game is on and it's in view; the page pulls `/api/state` again when you come back to the tab after 10+ minutes (`fresh()` clears every view's cache, as Refresh does). `watch()` (a daemon thread) rebuilds the league every 15 s when `data/whatif.json` changed under it (a what-if or a plan pick from the AI GM chat), and the page asks `/api/stamp` (`fetched`, what-ifs, pick ids) every 20 s and pulls the new state. Y3 (Nov 24): the snapshot-folder half is gone (`waiting()`, `newest()`, `took`, `state()`'s `waiting` and the page's "A newer snapshot is in the folder" notice); `refresh()` is a Yahoo pull when `.env` has `YAHOO_LEAGUE_ID` (a failed one keeps the last), then the league rebuilt from `data/league.json` with injuries, stats and live scores refetched; without the API that's the last `python yahoo.py import` (nothing files or reads snapshot files). Refresh takes ~2 s since ESPN's feeds are asked for gzipped (`model._json()`, Nov 13: the injury feed is 1.2 MB plain and took 5–19 s of every Refresh and every 30-minute refetch; 57 KB gzipped). Roster check and Who to drop (Q29, Nov 16): `/api/state` carries `check` (`roster_check()`, cheap: the page's roster alert on My team and This week, the My team nav dot, the header's "13 active, 2 in IL slots"); `/api/check` returns it alone; `/api/drops` runs `drops(punt)` (~1 s on the real league), which the page loads only while `check` has a `drop` problem (`S.drops`, dropped on every state load); `/api/move` takes no `add` (a drop alone). Q32 (Nov 17): `/api/state` carries `watch` (`model.watching()`: the watchlist rows; it writes `data/watch.json` when a new snapshot is first seen, so each row's `changes` are against the one before) and Waivers' 40 best free agents (`waivers(punt, 40)`, filtered and sorted on the page); `/api/watch` {add | remove} saves and returns the rows; `/api/waivers` {cats} is Waivers' Play for (`S.wv`, its position / sort / Play for kept in the browser); `/api/week` takes `cats` (Start / sit's Play for steers the streams, the plan and, since Nov 17, the lineups: `/api/lineup` is gone, its lineups come in `/api/week`'s `lineups`, on the plan's roster). Game day (Q31, Nov 17): `/api/week` also returns `night` (`game_night()` on the week it just built, +~0.2 s), the page's Today panel; `/api/today` runs it alone (`keep`, `weights`). `/api/week` and `/api/today` take `skip` (free agents marked Taken, `S.skip` / `gm.skip` in the browser; `League.without()` drops them from `fa` before the week is built, Nov 19). `/api/week` takes `choose` (a path's `key`: Every path's Use this, kept in the browser as `gm.weekPick` and dropped once a reply has no `chosen`), `adds` (B20: the streaming panel's Adds to use, `gm.weekAdds`, null = the model's pick; picking one clears `gm.weekPick` and Use this clears it) and `deep` (the Deep search toggle, `gm.weekDeep`: ~15–20 s a request on the real league, the 5-minute reload too; the panel greys and says it's searching meanwhile). The page's 5-minute This week reload also fires once the next game is past its tip (`night.lock.next`), so its players lock without a manual reload. Plan picks (Q30, Nov 16; since Y3, Nov 24, nothing else): every league the app builds is on the saved picks (`load = model.load(what=whatif(), made=moves())`); `/api/moved` takes a pick (`{add, drop, activate, park}`: Who to drop's Use this, which replaces the last pick) or `{undo: id | "all"}`, saves it through `League.made()` / `model.moves()`, rebuilds under the `refreshing` lock and returns the new state (a pick that can't be made is a 400 with the reason); `/api/state` carries `moves` for the banner, `/api/stamp` their ids, and `watch()` rebuilds when the file's ids differ from the league's (a pick the chat recorded with `model.py what --plan --drop ...`; `load()` dropping a pick the pull shows changes the file but not the league, so no second rebuild). Recorded made moves (add / drop / trade marked as done on Yahoo), the `stale` state, `done` and the `give` / `get` / `their_drop` fields are gone: moves made on Yahoo come with the pull. The record (Q33, Nov 23): `refresh()` ends with `record()` (`model.history()`: a new snapshot's row in `data/history.jsonl`, and a finished week's final, ~1 s; failures only print), and so does startup, in a thread (the first run backfills every snapshot in `snapshots/`, ~25 s); `/api/recap` (`?week=N`) runs `recap()` on that file; the page loads it once per state load (`S.recap`) for My team's trend lines, This week's Last week and League's Season so far. It reads text snapshots and, since Nov 23, the API pulls' day files (`model.pulls()`, `read_snap()`: the week from the matchup's dates on the schedule); `live()` runs `record()` after a pull that changed something. Yahoo's API (Nov 23): `live()` also asks `yahoo.lineups()` first (Y5: yesterday's lineups, once a day; failures only print), then pulls every `YAHOO_MIN` (15) minutes when `.env` has `YAHOO_LEAGUE_ID` (`yahoo.snapshot(changed=True)`: written, rebuilt and `sync_offers()` run only when `yahoo.NEWS()` differs: who's where with slot and tag, transactions, trades, records, adds, waiver order, this week's totals), so the page's 20-second stamp check reloads it; the page's "Done on Yahoo" and "They accepted" buttons are gone (moves come with the pull; "Use this", a plan pick, stays). Saves the AI GM's chats (`data/chats.json`) and Trades' Offers (`data/offers.json`, Q8: each copied offer with what the model predicted and Martin's Accepted / Declined, the data for tuning `accept()`). Since Nov 23 `refresh()` runs `sync_offers()` after an API pull: a pending Yahoo offer to or from you is logged (scored by `trade()` then, no punt) or tied to the copied one (`yahoo` = its key); once gone from Yahoo it's marked `auto` Accepted (the trade or a veto is in `trades`, or the players moved) or Declined; one they sent is `by: "them"`, a yes. Marking by hand drops `auto`. M30 (Nov 24): every route reads `aim` ("season" / "title", body or query, `League._aim()`, a bad one is a 400) like the punt, and the page sends `S.aim` with every POST and `&aim=title` on `/api/state`: `/api/state` (and the routes that return it) passes it to `state(punt, aim)` (aiming for the title, Waivers' suggested moves carry `title`, +~0.25 s), `/api/strategy`, `/api/trade` and `/api/move` take it (the title verdict, `season_verdict`), `/api/waivers` too, and `/api/search`'s goal defaults to `title` with it when the body names none. `/api/playoffs` = League's Playoffs period, `{**playoff_view(), dates}` (~0.1 s). `state()` carries `dates` (key dates). `claude_chat` gets the aim and tells the chat to add `--aim title` to strategy, trade, move, waivers and search. The page keeps the aim in `S.aim` (localStorage `gm.aim`, `?aim=title` overrides it, and changing it rewrites a `?aim=` in the address), the top bar's **Aim for** switch sits first in the punt row (`.seg.sm`), and `setAim()` drops Strategy, the finder's list, Saved trades' scores, an open trade and Try a move, sets the finder's goal to the aim's default (win / title) unless you'd picked cats or team, reloads the state and re-scores the open trade and move.
- The AI GM chat (S4, Nov 19: `ai.py`, the API-key path with its own shorter tool list, was deleted; unused since Oct 27): `/api/chat` runs `claude -p --safe-mode` (`app.py` `claude_chat`) with the gm SKILL.md as system prompt and only `model.py` allowed, plus `WebSearch` and `WebFetch` when the tab's Web search is on (`WEB` points it at RotoWire's lineups page and the NBA's official injury report) (Model / Effort / Web search are picked on the AI GM tab, validated by `MODELS` / `EFFORTS`). Every chat also passes the app's Waivers / Trades settings as `model.py` flags (`--healthy-fa`, `--no-free`, `--their-free`, `claude_chat`'s `opts`), and Trades' **Ask AI GM** opens the tab with the checked trade in the message box (`S.gmDraft`). Edit SKILL.md and both `/gm` and the in-app chat follow.
- `backtest.py`: replays a real NBA season (game logs cached in `data/gamelogs_*.csv`) in 20 simulated leagues and prints predicted vs actual win rates. It's the evidence behind the matchup knobs.
- `web/index.html`: the whole UI. State in `S`, views are `view*()` functions returning HTML strings, event delegation via `data-act` / `data-view` / `data-punt`. Views are listed in `VIEWS` (nav order, keys 1–0); `setView()` pushes a history entry and keeps each view's scroll in `S.scroll`, a `hashchange` (Back, a typed `#name`) switches views, and `toView()` maps unknown names to This week (Q36). Strategy is its own view and calls `/api/strategy` when opened with no answer yet. Trades evaluates a deal as soon as both sides have a player (`/api/trade`, ~0.15 s) and the pickers show Value only (Q22, Nov 7: per-player win % against the best free agent was tried and dropped).
