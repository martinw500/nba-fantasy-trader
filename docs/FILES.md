# Files: what each one does, in full

The caches, the app's threads and endpoints, the snapshot import and the AI GM. Moved here from CLAUDE.md on Nov 15, 2026, word for word. **Read it before changing `app.py`, `yahoo.py`, a cache or the page's data flow.** Model maths: `docs/MODEL.md`.

- `model.py`: the engine (`League` class) plus a JSON CLI. All numbers come from here: UI, AI chat and the `/gm` skill.
- `yahoo.py`: league snapshot → `data/league.json`. Yahoo API (read-only, yfpy; access now needs Yahoo's approval), `python yahoo.py import <snapshot>.txt ["Team"]` (Instinct-style league snapshot or a hand-typed list, `parse_text`; `from_text(write=False)` builds the league without touching `data/league.json`, for `backtest.py lineups`; unknown sections are skipped; snapshots live in `snapshots/` (`model.snapshots()` also sees one saved into the project folder; `app.refresh()` files it away, Nov 15); Refresh imports the newest `*snapshot*.txt` and refetches injuries, stats and box scores (`load(refetch=)`); the top-bar dropdown switches your team via `/api/me`, which keeps the week's `from`, dates and Yahoo games and takes the new team's opponent from the schedule, `model.switched()`, B1), or `python yahoo.py demo` (fake league from real stats).
- `model.py` also fetches the NBA schedule (`nba_api`, cached a day), ESPN's injury feed (cached 3h, archived per day), ESPN's projections (`espn()`, cached a day, archived per day), this season's box scores (`gamelogs()`, cached 12h, for the player card's recent lines; with this season's stats once a final game is missing from them, at most every 30 min) and live scores (`scores()`, M18: nba_api's live scoreboard + box scores of games under way or final, `data/live.json`, every `LIVE_POLL` 5 min while one is on (`live_on()`), else 30; the last two days kept; a failed box keeps that game's last one) in `load()`, and passes `news()` (ESPN fantasy news: the player list with ids and latest-news times cached 3h in `news_index()`, a player's items refetched only when that time moves) for the card and My team's News panel (`roster_news()`). News never changes a number. `League` built directly (tests) gets none of them, so it stays offline. Freshness (Q9): `SOURCES` lists those caches and their refresh windows. A failed refresh keeps the old copy and is logged in `FAILED` (this season's stats too, which only raise with no copy at all). A bad reply is a failed refresh (Nov 9): an empty JSON feed (`_cached()`; injuries and projections before their day's archive), a stats or box-score table that came back 5% shorter than the saved copy, empty included (`_save_csv()`; with nothing saved yet, before opening night, an empty one is fine). Every cache, `league.json` and the app's own files are written as a copy and swapped in (`_write()`): the app's `live()` thread, Refresh and the AI GM's `model.py` runs read them while another writes. `freshness()` reads file times against the windows (ok / stale / failed / missing); `load()` keeps the times it built from (`League.loaded`, news read live) and `state()["sources"]` feeds the sidebar.
- `app.py`: stdlib `ThreadingHTTPServer` on 127.0.0.1:8765, routes in `api()`. `live()` (a daemon thread) refetches ESPN's injury feed every `LIVE_MIN` (30) minutes and rebuilds the league on the same snapshot, and on game nights also a minute after each tip-off and every `LIVE_POLL` minutes while one is on (`model.next_poll()`; live scores refetch on their own window, the injury feed stays on `LIVE_MIN`), and drops a rebuild that started before `league.json` changed under it (`gen`: bumped by `remember()` (team switch, opponent) and Refresh, after the write; Nov 4, audit #23); This week reloads every 5 minutes while a game is on and it's in view; the page pulls `/api/state` again when you come back to the tab after 10+ minutes (`fresh()` clears every view's cache, as Refresh does). A snapshot saved into the folder loads by itself (Nov 13, Martin): `watch()` (a daemon thread) looks every 15 s for a file `waiting()` (the newest one, `newest()`, when it isn't the one `refresh()` last read), runs `refresh()` once it's 5 s old (each save tried once), and the page asks `/api/stamp` every 20 s and pulls the new state; `state()` still carries `waiting` for the page's notice if that failed. Refresh takes ~2 s since ESPN's feeds are asked for gzipped (`model._json()`, Nov 13: the injury feed is 1.2 MB plain and took 5–19 s of every Refresh and every 30-minute refetch; 57 KB gzipped). Roster check and Who to drop (Q29, Nov 16): `/api/state` carries `check` (`roster_check()`, cheap: the page's roster alert on My team and This week, the My team nav dot, the header's "13 active, 2 in IL slots"); `/api/check` returns it alone; `/api/drops` runs `drops(punt)` (~1 s on the real league), which the page loads only while `check` has a `drop` problem (`S.drops`, dropped on every state load); `/api/move` takes no `add` (a drop alone). Q32 (Nov 17): `/api/state` carries `watch` (`model.watching()`: the watchlist rows; it writes `data/watch.json` when a new snapshot is first seen, so each row's `changes` are against the one before) and Waivers' 40 best free agents (`waivers(punt, 40)`, filtered and sorted on the page); `/api/watch` {add | remove} saves and returns the rows; `/api/waivers` {cats} is Waivers' Play for (`S.wv`, its position / sort / Play for kept in the browser); `/api/week` takes `cats` (Start / sit's Play for steers the streams, the plan and, since Nov 17, the lineups: `/api/lineup` is gone, its lineups come in `/api/week`'s `lineups`, on the plan's roster). Game day (Q31, Nov 17): `/api/week` also returns `night` (`game_night()` on the week it just built, +~0.2 s), the page's Today panel; `/api/today` runs it alone (`keep`, `weights`). `/api/week` and `/api/today` take `skip` (free agents marked Taken, `S.skip` / `gm.skip` in the browser; `League.without()` drops them from `fa` before the week is built, Nov 19). `/api/week` takes `choose` (a path's `key`: Every path's Use this, kept in the browser as `gm.weekPick` and dropped once a reply has no `chosen`), `adds` (B20: the streaming panel's Adds to use, `gm.weekAdds`, null = the model's pick; picking one clears `gm.weekPick` and Use this clears it) and `deep` (the Deep search toggle, `gm.weekDeep`: ~15–20 s a request on the real league, the 5-minute reload too; the panel greys and says it's searching meanwhile). The page's 5-minute This week reload also fires once the next game is past its tip (`night.lock.next`), so its players lock without a manual reload. "I made this move" (Q30, Nov 16): every league the app builds is on the saved roster moves (`load = model.load(what=whatif(), made=moves())`); `/api/moved` takes a move (`{add, drop, activate, park, give, get, their_drop}`, `plan: true` for a pick not made yet, which replaces the last pick), `{undo: id | "all"}` or `{done: id}`, saves it through `League.made()` / `model.moves()`, rebuilds under the `refreshing` lock and returns the new state (a move that can't be made is a 400 with the reason); `/api/state` carries `moves` for the banner, `/api/stamp` their ids and states, and `watch()` rebuilds when the file's moves differ from the league's (a move the chat recorded with `model.py what --drop ...`; `load()` dropping a move the snapshot shows changes the file but not the league, so no second rebuild). Saves the AI GM's chats (`data/chats.json`) and Trades' Offers sent (`data/offers.json`, Q8: each copied offer with what the model predicted and Martin's Accepted / Declined, the data for tuning `accept()`).
- The AI GM chat (S4, Nov 19: `ai.py`, the API-key path with its own shorter tool list, was deleted; unused since Oct 27): `/api/chat` runs `claude -p --safe-mode` (`app.py` `claude_chat`) with the gm SKILL.md as system prompt and only `model.py` allowed, plus `WebSearch` and `WebFetch` when the tab's Web search is on (`WEB` points it at RotoWire's lineups page and the NBA's official injury report) (Model / Effort / Web search are picked on the AI GM tab, validated by `MODELS` / `EFFORTS`). Every chat also passes the app's Waivers / Trades settings as `model.py` flags (`--healthy-fa`, `--no-free`, `--their-free`, `claude_chat`'s `opts`), and Trades' **Ask AI GM** opens the tab with the checked trade in the message box (`S.gmDraft`). Edit SKILL.md and both `/gm` and the in-app chat follow.
- `backtest.py`: replays a real NBA season (game logs cached in `data/gamelogs_*.csv`) in 20 simulated leagues and prints predicted vs actual win rates. It's the evidence behind the matchup knobs.
- `web/index.html`: the whole UI. State in `S`, views are `view*()` functions returning HTML strings, event delegation via `data-act` / `data-view` / `data-punt`. Trades evaluates a deal as soon as both sides have a player (`/api/trade`, ~0.15 s) and the pickers show Value only (Q22, Nov 7: per-player win % against the best free agent was tried and dropped).
